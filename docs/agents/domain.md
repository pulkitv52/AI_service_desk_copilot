# Domain docs

Use a single-context layout:

- `GLOSSARY.md` at the repository root
- Architecture decision records in `docs/adr/`

Before exploring an area, read the glossary and relevant ADRs.
If they do not exist, proceed silently; create them only when
domain terms or architectural decisions are resolved.

Use the glossary's vocabulary in code, issues, and proposals.
Explicitly flag proposals that conflict with existing ADRs.
